# qws-interview

`/qws-interview` 是一个 AI 采访 skill。

你原本就有很多经验、想法和判断，只是还没有完整表达出来。AI 采访 skill 通过连续、非诱导式追问，把其中能够外化的部分整理成可检查、可修正、可复用的显性知识；无法完全说清的部分，仍保留为默会知识。采访结束后，还会生成一篇可以独立阅读的文稿。

对于创作者，它解决的是缺少可持续内容素材的问题。你不用先写提纲，也不用先想清楚观点。只要回答 AI 的问题，它就能把你没有说清的经验和判断整理成文稿，并从中继续发现可以开发的素材和选题。

支持：豆包、WorkBuddy、Claude Code、Codex，以及其他支持 skills 的 Agent。

## 适合处理什么

你不需要预先拥有一套知识，也不需要先证明自己是专家。它尤其适合独自表达时容易说散、停住或漏掉关键判断，希望有人连续追问并维护主线的人。

AI 采访可以采访：

1. 生活经历和个人感悟；
2. 工作经验和商业判断；
3. 创作过程和选择依据；
4. 人生转折和关系变化；
5. 尚未成形的想法；
6. 需要通过追问才能发现的认识。

## 采访结束后会得到什么

默认生成两份文件。

### 1. 完整采访记录

`01-完整采访记录.md` 保存实际发生的采访问答，采访者发言与用户原文按轮次合并保存。它保留用户原始回答，不把 Agent 的内部分析、编辑过程和工具记录混入采访内容。

### 2. 采访分析与知识整理

`02-采访分析与知识整理.md` 会把采访中的结论、理由、案例和边界，组织成一篇可以独立阅读的知识稿。其中只含知识、案例、数据、材料解释、已核验理论的嵌入应用和未解决的知识问题，不含本地文档来源、流程、编辑表或内部检查记录。

材料能够支持到哪里，结论就写到哪里。材料不足以支持的事实或结论，AI 不会作出判断，也不会替用户制造观点或普遍规律。采用正式理论时，正文显示可点击名称，文末保留简短理论注释与可靠来源链接；理论不能被包装成用户原本的观点。

知识稿从读者的问题出发，组织用户回答中的结论、理由、案例与边界，呈现对话探索得到的认识。它不是问答摘录或经历复述，不按“我的认识／外部研究”拆开。个人经历承担例证作用，研究有实际增量时就地融入，保留知识归属。

知识稿完成后，skill 会自动扫描值得继续采访的旁支。这些旁支可以继续深挖，未来作为素材或选题。完成后的知识稿还可以继续整理成公众号文章、口播稿、视频脚本、思维导图或课件，也可以放入知识库，作为长期内容资产使用。

完整记录保存过程，知识稿交付成果。有旁支时会提醒用户可以自建选题素材库，但不自动创建素材库、表达稿或第三份文件。用户另行要求口播、发布稿或图示时，属于后续内容制作，继承已有材料。既有文件不自动删除。

## 安装

在终端执行：

```bash
npx -y skills add QWFlow/qwskill -g --all
```

安装后回到 Agent，输入 `/qws-interview`，或者直接用自然语言说明你想接受采访的经历、感受、想法或判断。

## 调用方式

```text
/qws-interview
```

也可以直接说：

- “采访我这次辞职以后真正想明白了什么。”
- “帮我把这几年做生意形成的判断问出来。”
- “我最终选择这个创作方向，但自己还说不清原因。”
- “我最近对一段关系有些感受，想通过采访把它讲清楚。”
- “我脑子里有个不成熟的想法，你一次问我一个问题。”
- “我不知道自己有什么知识，你先采访，看看能发现什么。”

## 核心行为

- 一次只问一个最有推进力的问题。
- 通过具体事件、判断信号、正反案例和失效边界深挖，不向问题中预装理论或答案。
- 用户说过的内容逐轮保存，Agent 不替用户下结论。
- 有价值的旁支先提醒、暂存，主线闭环后再由用户选择是否展开。
- 用户知识冻结后，依次启动观点契约子智能体和 Writer 子智能体；二者使用隔离上下文，Writer 只接收`01＋观点契约`。正文冻结后由主 Agent 主动检索并核验重要机制对应的成熟理论；只有可靠且有增量的理论才添加句后小括号与文末注释，再用确定性检查确认正文未被改动。
- 公开表达素材会主动询问，但不会为了传播效果污染知识采访。
- 采访结束后统一整理，不在每轮反复改写成稿。
- 知识稿完成后自动扫描值得继续深挖的旁支，不等用户另外追问。

## 处理时间

采访结束后，skill 会分别完成观点整理和正文写作。完成时间会根据采访内容的多少而不同。需要核验的内容和宿主的执行能力也会影响实际完成时间。

## 运行条件

- Agent 能安装并调用 skills。
- 完整生成知识稿时，宿主能先后启动两个彼此隔离的子智能体，并把第一阶段形成的完整观点契约交给第二阶段 Writer。宿主只有 skills 安装能力、但不支持这种隔离执行时，仍可读取和调用本 skill，但不能按完整流程交付最终知识稿；skill 会明确说明限制，不会在同一上下文中模拟两个角色。
- 首次生成知识稿时，宿主能进行网络检索，以核验确有解释增量的成熟理论；没有可靠理论时不强行添加。
- 理论覆盖的确定性还原检查需要 Python 3。

## 隐私与权限

采访记录和知识稿默认写入用户指定的本地目录。理论核验可能使用外部网络检索；只应查询必要的概念、论文与来源，不向外部服务发送与核验无关的私密原文。skill 不会自动发布采访内容，也不会自动创建远端仓库。

## 边界

采访阶段只负责把知识说清并整理成稿。录音录像、转写、字幕、剪辑、正式选题、口播或发布稿制作、标题、封面、制图和发布审核属于后续内容制作。没有可写入的正式理论时，不硬编名称、模型或来源；仍须从采访证据形成材料内生解释。理论只局部解释与当前主线有关的机制，不能把知识稿扩写成理论综述。材料不足时收窄结论或不作判断，不用推测补齐。

## 设计依据（不参与每次运行）

运行时文件只保留可执行规则；以下内容说明这些规则的来源，不是知识稿必须出现的理论，也不增加采访、写作或理论标注步骤。

### 知识提取与校验

- 迈克尔·波兰尼的默会知识理论提醒我们：我们所知道的，多于我们所能言传的。
- 野中郁次郎与竹内弘高的 SECI 模型用于解释隐性知识如何通过“外化”转为显性知识，参考 [The Knowledge-Creating Company](https://academic.oup.com/book/52097)。
- 认知任务分析与关键决策法用于从真实事件、线索、选项、判断和后果中提取专家知识。
- Whetten 的 what／how／why 与 who／where／when 用于检查解释与边界。
- Popper 与 Kuhn 提供反例、框架和异常的检验意识。

### 问题与观点组织

- QUD 用于维护主问题、子问题、推进关系和返回位置，参考 Craige Roberts 的 [Information Structure in Discourse](https://semanticsarchive.net/Archive/WYzOTRkO/InfoStructure.pdf)。
- van Fraassen 的 `P–X–R` 用于区分待解释现象、对比预期和解释类型，参考 [The Pragmatic Theory of Explanation](https://fitelson.org/290/vanfraassen_pte.pdf)。
- Jobs to Be Done 只校验文章是否帮助读者推进理解或判断，不决定文章中心、观点顺序和材料去留，参考 [Know Your Customers’ “Jobs to Be Done”](https://hbr.org/2016/09/know-your-customers-jobs-to-be-done)。

### 写作与可读性

- Linda Flower 的 Writer-Based／Reader-Based Prose 用于检查作者材料是否已经转成读者可重建的表达，参考 [Writer-Based Prose](https://doi.org/10.58680/ce197916016)。
- Kintsch 与 van Dijk 的文本微观与宏观结构用于检查局部和全文连贯，参考 [Toward a Model of Text Comprehension and Production](https://doi.org/10.1037/0033-295X.85.5.363)。
- [ISO 24495-1:2023](https://www.iso.org/standard/78907.html) 用于检查相关、易找、易懂和可用。
- 冗余效应用于检查无独立作用的重复，但不能机械删除观点、证据、逻辑连接或边界，参考 [The Redundancy Principle in Multimedia Learning](https://doi.org/10.1017/CBO9781139547369.013)。

这些框架只解释采访、观点契约和 Writer 规则为什么成立，不证明采访主题中的商业、心理或社会结论。主题理论仍须针对正文中的具体解释缺口单独检索和核验，不得用这些设计依据直接替代。
