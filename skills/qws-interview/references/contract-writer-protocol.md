# Contract 与 Writer 协议

本协议恢复自 2026-09-18 生成优质知识稿时两个独立子智能体实际读取的角色契约。它只约束观点契约分析者与 Writer，不增加 Reviewer、局部编辑者、`PASS／FAIL`或修复循环。

“独立”是指不共享前一角色的对话历史、草稿推理和自我评价的新上下文。可以使用同一模型，但必须是新会话、子任务或宿主提供的隔离执行单元。在原上下文里换一个角色名、声称“冷读”或再读一遍，不算独立。

## A. 观点契约分析者

输入只有`01`和用户当次明确要求。不得读取旧`02`、候选稿、后续阶段产物或历史编辑清单。

输出一份临时观点契约，至少包含：

- 主 QUD；解释型问题同时包含`P–X–R`；
- 读者原有困惑、本文应给出的新判断和可感知用途；
- 每个候选判断的编号、主体、对象、方向、强度、成立条件、材料位置、对主 QUD 的作用，以及后续材料对它的 `support`／`qualify`／`revise`／`refute` 关系、`核心结论／必要推进／可选支撑／内部边界／独立旁支`正文责任、展开深度和保留／合并／排除理由；
- 已排好顺序的观点主线。解释型主 QUD 使用`最反常的事实 → 被推翻的默认判断 → 最先说出的反预期结论 → 必要证据与解释 → 仍未解决的矛盾 → 更深一层判断`；只有回答上一层残余矛盾的判断才进入下一层。材料没有反预期关系时按真实的时间、条件、因果或判断依赖排序，不强造反转；
- 说话人与人称映射；
- 观点归属映射：区分用户明确表达的判断与 Agent 推导；用户对具体当事人心理、动机、需求或关系的判断仍属于用户知识，不因当事人未亲口确认而降调；
- 材料角色：主线证据、必要支撑、必要边界、背景或旁支；
- 能回指`01`并由正文兑现的开头亮点候选。

契约不写作正文，不推荐理论，不进入`01`或`02`。不得把契约扩张成逐句保留台账、原句锚点清单或“直接使用”指令；只有服务主 QUD 的核心结论与必要推进进入观点主线。

## B. Writer

输入为`01＋观点契约（含观点主线）`及主文件的写作规则。不得读取候选理论、旧稿或后续审核结论。Writer 严格沿观点主线成稿，不重新选择中心或顺序。正文在最少必要情境后先写本层判断，再写证据和解释；只有判断已给出且材料仍有真实缺口时，才用问句开启下一层。并列理由如实成组，不制造递进；不写元标签、防御性回拽和重复边界。输出只包含不带理论的基线稿。

Writer 可自查，但自查不得反向扩张观点契约、恢复已排除材料，或把审计边界写进正文。

## 运行边界

两个角色必须先后运行，不得合并或并行。观点契约返回后才启动 Writer。宿主无法创建隔离上下文时，如实说明知识稿未按规定流程完成，不得在主 Agent 当前上下文里串行扮演两个角色。
