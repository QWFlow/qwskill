# AI 知识采访工作流

## 1. 建档

正式进入多轮采访时，默认在当前工作区建立：

```text
知识采访记录/YYYY-MM-DD-暂定主题/
├── 01-完整采访记录.md
└── 02-采访分析与知识整理.md
```

固定只建立和交付这两份文件。知识稿完成后自动扫描值得继续深挖的旁支，并在对话里自然说明知识稿的后续用法；不自动生成第三份稿件或素材库。

若用户指定保存位置，使用用户位置。若用户明确不要写文件，只在当前对话中执行，但要说明跨窗口和压缩后无法保证恢复。

### 文件一：完整采访记录

这是主题采访的逐轮事实记录。写入前执行主文件“第三步”的白名单：只保存实际主题采访问答与用户素材。内部分析、阶段快照、写作安排和执行维护信息不得作为正文、工作记录或附录写入。清理旧记录时保留原编号，不为补齐编号改写历史。

```markdown
## T001

### 采访者
这里保存发送给用户的完整采访问题。

### 用户
这里保存 Agent 实际收到的采访范围内用户原文，不改写、不纠错、不补全。
```

实际发送给用户的主题旁支提示、阶段结论及用户对“继续／下次／结束”的选择，按原话放在对应轮次。未发送的内部总结不写入。

通过记录范围闸门后，写入顺序不可颠倒：

1. 问题先落盘，再发送。
2. 回答先落盘，再分析。
3. 保存失败时停止后续推理并告知用户。

图片、附件或语音输入无法逐字嵌入时，记录其文件引用和 Agent 实际收到的文本；不得声称已经完成音频级校对。

### 文件二：采访分析与知识整理

建档时只写：

```markdown
# 采访分析与知识整理

- 主题：

```

不要每轮重写。只有用户明确结束，或要求阶段报告时，再统一补全。

## 2. 主线与旁支

### QUD 主线与子问题

一个阶段只维护一个最终要回答的主 QUD（Question Under Discussion）。宽泛主题、素材类别、文章标题或“聊什么”不等于主 QUD；必须把它写成一个现有材料可以逐步回答的问题。追问前在内部维护：

```text
主 QUD：整场采访最终要回答什么
当前子 QUD：本轮正在解决哪个子问题
推进关系：该答案将如何改变、支撑或限定主 QUD 答案
返回位置：子 QUD 解决后回到哪个父问题
```

只有能写清“推进关系”才进入子 QUD。子问题解决后立即回到父 QUD，不沿子问题继续自由发散。新内容不能推进当前主 QUD，但能形成独立知识链时，按旁支处理；既不推进也无独立价值时不追问。

下一问优先补齐当前 QUD 链条中的关键缺口：

- 发生在什么具体情境；
- 用户做了什么或如何判断；
- 为什么会得到这个结果；
- 哪些证据让用户相信；
- 什么条件下不成立；
- 这套经验能否被他人理解或复用。

不要求每项都问。只问会改变结论或补齐关键因果的部分。

#### 解释型 QUD 的 `P–X–R`

当主 QUD 要回答“为什么发生 `P`”或“`P` 怎样会发生”时，再在内部标记：

```text
P：已发生或待解释的现象
X：与 P 对比的另一种结果、默认预期或未发生状态
R：用户此刻要的解释类型，如机制、动机、条件、过程或功能
```

对照项 `X` 用来界定真正需要解释的差异，不是为了制造冲突。下一问只补 `P–X–R` 中会改变中心答案的一个缺口。材料已能唯一恢复时直接使用；无法唯一恢复时用开放问题追问具体事件或差异，不把 Agent 候选答案放进问题。主 QUD 是定义、描述、评估、选择或步骤类问题时，不强行补 `P–X–R`。

### 提问精度

每次提出下一问前，先在内部锁定：

```text
当前对象：用户刚才提到的哪个具体对象
待补缺口：事实／判断／因果／边界／例外中的哪一项
提问动作：描述／区分／比较／解释／判断／选择中的哪一种主要动作
判断维度：本轮只沿哪个维度推进
回答用途：回答会改变哪项结论或下一步
```

“回答用途”必须同时说明该问如何推进当前子 QUD 或主 QUD；只能增加材料，却不会改变、支撑或限定中心答案，也不会改变下一步的问题不发送。其余任一项不清楚也不发送。一个问题不得混入多个主要对象、动作或判断维度；有多个可能指代的抽象词必须改成具体名词。对象唯一时直接问；存在歧义时先用一句话回显当前理解，再问一个问题；前一项答案决定后一项是否需要时拆成两轮。

用户表示没看懂时，立即撤回上一问，判断歧义来自对象、动作、指代还是判断维度，再重新生成一个只有单一理解的问题。不得解释原问题、追加更多例子或选项，也不得把失败归因于用户理解能力。

### 非诱导式深挖

采访阶段只从用户已经提供的材料继续外化，不向问题中加入新的理论、因果解释、价值判断或答案选项。

优先使用以下入口：

1. 请用户还原一次具体事件及其时间顺序；
2. 追问当时看见的信号、采取的动作、排除的选择和实际结果；
3. 比较用户亲历的成功／失败、相同／相反案例；
4. 追问例外、失效条件和能够观察的判断标准。

可以并列引用用户原话中的差异或矛盾，再问“当时什么条件发生了变化”；不得问“是不是因为……”或“会不会其实是……”。用户答不出来时更换事实入口；仍无法外化的部分保留为默会知识，不提供候选知识让用户认领。

### 公开表达素材

如果整理后的知识将用于公开表达、后续录制或内容生产，主动收集三类材料：

- 表达依据：用户为什么有依据讲这件事；
- 亮点素材：结果、冲突、代价、转折、事件、场景、经历或反常识判断；
- 开头素材：目标受众能够识别与自己有关、并需要正文继续解释的问题或信息缺口。

这三类材料可以在过程里自然出现，也可以经过多轮补充。已有材料说清时直接记录，不重复追问；出现自然机会时顺势追问；直到主线收束前仍未覆盖时，再分别用一个开放问题补问。收束前至少确认两项已有明确回答：一项说明用户为什么有依据讲这件事，包括亲历、做成的结果、可迁移经验或可追溯研究；一项提供亮点或开头所需的具体结果、冲突、代价、转折、场景、经历、反常判断或信息缺口。缺哪一项就按一次一个问题补哪一项，不能用 Agent 自己的归纳代替用户回答。

表达依据可以来自亲身经历、已经取得的结果、能够迁移到当前问题的经验，或可追溯的研究材料。

不要求结果必须来自完全相同的行业，但跨行业依据必须说明可迁移的机制。研究型内容可以使用用户已完成的资料比较、疑问和判断，但必须保留可追溯材料，不能伪装成亲历。若用户是在教别人行动、赚钱或复制一种方法，应优先说明亲历、结果或经过实践的可迁移经验；研究只能补充论证，不能包装成亲自验证。无关身份、空泛头衔和 Agent 推测不能作为表达资格。

Agent 可以从用户原话中标记候选，并说明它可以承担表达依据、亮点或开头中的哪项任务，以及正文接下来需要兑现什么；不能用“这是不是正确答案”一类认领式问题，把 Agent 的传播判断写成用户知识。采访阶段只建立素材池，不决定最终采用哪一项，不生成标题，也不承诺传播结果。

主动询问是流程要求，得到素材不是知识闭环门槛。只有对应问题已经问出，且用户明确表示没有、暂时想不到或回答不出来，才记录“本次未形成明确候选”及相应风险，继续完成知识主线。没有问、没有收到回答、Agent 没找到或没识别出来，都不等于用户没有素材。

### 有价值的旁支

符合下列任一条件时，可以登记：

- 它能形成另一条完整的经验或知识链；
- 它与目标观众存在更强的处境、代价或结果关联；
- 它包含明显差异、冲突、转折、反直觉或具体案例；
- 它需要独立的理论解释或证据核验。

提示格式保持自然，例如：

> 这里出现了一条值得单独聊的旁支：你发现“准备得越完整，反而越难开始”。我先记下来，当前先把主线说完。

旁支不得立即抢占主线，除非用户明确要求切换。

### 用户当前指向的局部对象

用户明确说“只记录这段”“这是补充”“这可能是亮点或钩子”“其他部分先不要改”时，本轮优先级由这项局部指令决定。先保存用户原文，再锁定：

```text
当前对象：用户明确指向的原文或片段
当前动作：记录／归类／判断／解释／修改
处理状态：待处理／已完成／待用户确认
原主线：处理完成后恢复的位置
```

- 用户只要求记录：写入完整采访记录，不提前重写分析文件；若用户没有要求暂停，随后继续一条主线问题。
- 用户表达局部不确定性：先回答这段内容当前是什么、依据是什么；需要确认时只问这一件事，不再追加主线问题。
- 用户补充的内容改变原结论：先处理当前对象，再更新主线；不能因为它是新增内容就自动当作旁支。
- 用户限制“其他部分先不修改”：不得借当前补充重排全文、重开概念层级或处理相邻问题。

局部动作完成后才能恢复主线。相关但更抽象的问题，不能替代对当前对象的记录、判断或解释。

## 3. 阶段闭环

当 Agent 判断当前问题已经具备足够的事实、机制、判断或行动依据，并且关键边界没有明显缺口时，先进入“候选闭环”，不能直接结束该阶段。

若采访用于公开内容，先检查表达依据、亮点和开头素材是否都已经主动询问，并能回指用户的明确回答。未覆盖的项目先各问一次；问题已经问出但用户明确表示没有、暂时想不到或回答不上来时如实记录，不得为了凑齐素材反复追问或阻断知识闭环。尚未提问或没有收到回答时不能进入候选闭环。

候选闭环的可见回复只需包含：

1. 一两句候选阶段结论；
2. 一次收束确认，同时给出两个表达入口：内容是否遗漏，以及用户自己是否仍有困惑。可问：“就这条主线，还有没有需要补充、我没问到的内容？你自己还有没有困惑，或觉得没想清楚、没聊清楚的地方？”这两句服务同一个收束判断，不在本轮追加旁支选择。

“补充／没问到”要求用户回顾采访覆盖了什么；“困惑”允许用户从自身尚未理解或琢磨清楚的地方开口，不能互相替代。用户只说“没有补充”，却没有回应自身困惑时，下一轮只补问困惑，不重问整套收束问题；已明确回应两方面时不重复确认。

如果用户补充了内容或提出困惑：

1. 将原文写入完整采访记录；
2. 优先处理用户提出的内容或困惑，一次只追问一个具体缺口，不因 Agent 认为链路完整就直接结束；
3. 处理后再次确认是否还有遗漏或困惑；一时无法说清的，保留为未知。用户明确选择暂留该困惑或结束时，按其选择整理并保留未解决状态，不强迫全部解决。

只有用户对遗漏和自身困惑都作出明确回应，且待处理内容已处理或由用户明确决定暂留，才冻结当前阶段的用户知识快照，当前阶段才算“已确认闭环”；阶段收束不代表暂留困惑已经解决。此时的可见回复再包含：

1. 已确认的阶段结论；
2. 当前可选旁支，列表以“可继续深挖的旁支（也可以之后作为素材或选题继续推进）”呈现；
3. 一个选择问题：现在继续哪条、留到下次，还是结束并整理。

收束确认与旁支选择必须分成两个轮次，继续遵守一次只问一个问题。

不做默认的阶段末补缺清单。若存在会让当前结论无法成立的决定性缺口，应在主线尚未结束时直接追问，不留到最后集中补问。

## 4. 采访节奏

- 问题要短，让用户容易接住。
- 不要求每段回答脱离上下文也能独立成稿。
- 不强迫用户重复主语、背景或已经说过的结论。
- 用户出现停顿、口误或重复，不影响文字知识采访继续。
- 可用采访时间只决定展开几条线，不改变主线先闭环的原则。

## 5. 恢复采访

跨窗口或下次继续时：

1. 读取 `01-完整采访记录.md` 中最近一次阶段结论及其后的全部轮次；
2. 读取用户最后选择的旁支或暂停点；
3. 必要时查看 `02-采访分析与知识整理.md` 的当前状态；
4. 从实际问答和阶段结论恢复主 QUD、当前子 QUD 及返回位置；若是解释型 QUD，同时恢复 `P–X–R`。无法唯一恢复且会改变主线时，只问一个决定性问题。
5. 用一句短话确认恢复位置，然后直接提出下一问。

最终整理时，应回看所有已经确认的阶段结论及其对应原文范围，避免只依赖当前上下文。

## 6. 知识稿整理与交付

用户直接提交已完成记录时，执行主文件“已有采访记录的直接整理入口”，跳过重新采访；区分主题证据与历史工作、编辑指令，不把后者作为当前要求。

回查全部已确认阶段结论及对应回答，把主 QUD、子 QUD、已确认答案及解释型问题的 `P–X–R` 交给整理阶段；旧记录缺少状态时，只按实际问答重建一次。

进入整理后完整读取[知识校验](knowledge-validation.md)：它决定观点契约、观点主线、Writer 写作、材料解释和理论核验标注。`01`仍按采访问答实时保存；Writer 完成正文与自查后，先冻结正文，再主动完成理论候选扫描、实际核验和必要标注，然后才把知识稿保存为正式`02`。随后按主文件执行进度告知、只读旁支扫描和最终回复。内部契约和检查过程不得追加到`01`或`02`，也不新增第三份知识文件。
