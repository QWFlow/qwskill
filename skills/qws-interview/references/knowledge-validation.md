# 知识校验与理论使用

## 1. 先承认默会知识的边界

个人经验并不一定能被完整语言化。采访的目标不是声称“全部提取”，而是尽量把能够表达、检查和复用的部分外化，并标记仍需情境、动作示范或进一步追问的部分。

### 中心问题的两层内部模型

QUD 管主问题、当前子问题、两者的推进关系和解决后的返回位置。解释型 QUD 另记录 `P`（待解释现象）、`X`（对比结果或默认预期）和 `R`（请求的解释类型）；候选答案必须解释 `P` 相对 `X` 的差异并符合 `R`。采访再从具体事件、线索、选项、判断和后果中追问答案。三者不能互相替代，也不因作为内部方法而自动进入知识正文。设计依据与来源见 README。

## 2. 用户知识的最小结构

一条稳定知识通常需要按材料实际情况具备若干项：

- 现象或对象是什么；
- 发生在什么情境；
- 用户看到了哪些线索；
- 用户采取了什么行动或作出什么判断；
- 结果是什么；
- 用户认为因果机制是什么；
- 哪些条件、例外或反例会改变它。

不要机械追齐所有栏目。判断标准是：缺少这一项是否会让结论失真、不可理解或不可使用。

### 观点主线筛选

知识稿第一优先级不是保存全部材料，而是保全主 QUD 的核心答案和使该答案成立的必要推进。先从用户回答、附件中的用户思考和已确认结论提取候选判断，再逐项记录：

```text
候选判断 → 主体／对象／方向／强度／成立条件 → 材料依据 → 对主 QUD 的作用 → 后续材料与它的 support／qualify／revise／refute 关系 → 与其他判断的逻辑差异 → 正文责任 → 展开深度 → 保留／合并／排除 → 正文落点
```

`正文责任`分为`核心结论／必要推进／可选支撑／内部边界／独立旁支`；`展开深度`分为`完整展开／简要说明／合并承担／仅内部保留／排除`。核心结论直接改变主 QUD 答案；必要推进负责解释当前矛盾、使下一层判断成立，或提供不可替代的关键证据；这两类构成必须可复原的“正文承诺”，两者合称“观点主线”。合格候选不自动进入观点主线；可选支撑、内部边界与独立旁支不属于观点主线。可选支撑虽相关，但在更强材料已完成同一作用时可压缩、合并或不写。背景、内部边界、独立旁支和证据不足的推测不因“与主题有关”进入正文。旁支中某一部分对当前主线不可替代时，只把该部分升为必要推进或其必要证据；保留量由它对当前观点的解释作用和匹配度决定，不固定句数，不连带展开整条旁支。

候选判断有材料支持、未被用户后来否定或替换，并且直接回答、支撑、解释或限定主 QUD 时，先成为合格候选，再分配正文责任；只有核心结论与必要推进纳入观点主线。背景、旁支、重复表达、失效判断和证据不足的推测不进入。两个判断围绕同一话题不等于重复；分别承担定义、原因、机制、条件、结果、检验方法或适用范围时，必须分别保留其逻辑作用。提取时先拆开用户用“或者／另一种／一是二是”等明确连接的替代理由、条件和结果，再决定能否成组表达；后来材料只继续解释其中一项时，只对该项形成 `support` 或必要限定，不把未被修订的另一项静默合并。普通“和／及／、”并列不因对象名称不同就机械拆分；只有材料为各项给出不同方向、强度、条件或逻辑作用，或其中一项能在另一项不成立时独立改变答案，才建立不同候选。遇到省略比较对象、时间参照、指代或其他决定结论的成分，先保留原句并记录语义缺口，再用同一命题的其他材料检验可能解释；不得仅沿用相邻分支替它补全。仍有两种以上会改变正文判断的合理解释时，分别保留或标为未知，不静默选定。同一判断承担两个不同解释任务，或同一比较关系分别涉及当下与未来等不同时间参照时，分别记录作用与时间映射；正文只在一处提到，不算覆盖另一项作用或时间关系。一项强判断能被若干机制、条件或后果展开，不等于它只是这些局部判断的重复总结；它若独立改变读者对现象的解释，仍须作为核心结论或必要推进保留。正文还须保留该正文承诺的主体、方向、强度和成立条件；把强判断改成宽泛的“有影响”“作用变了”，即使话题词仍在，也属于写弱。文章更短、更顺或已经有一个总括结论，都不能作为删除或写弱正文承诺的理由。

后续材料必须按同一命题比较，不按共用话题词比较。它若只是为原判断增加适用对象、阶段、前提或失效条件，记为 `qualify`，把条件附着到原判断而不降低强度。只有用户明确改变判断，或后续材料在同一主体、对象、阶段和条件下给出相反方向，才记为 `revise` 或 `refute` 并允许写弱、替换或排除。“仍需要一个东西完成后续动作”与“这个东西不是前一阶段意愿形成的决定因素”可以同时成立，不得因前者存在就把后者改成“可能有一定影响”。

这张清单必须先由只读取`01`和用户当次明确要求的独立观点契约分析者建立，再交给另一个 Writer。Writer 不能自行补删契约、重新选择中心或顺序；需要改变保留、合并或排除决定时，返回契约层处理，不在正文里补偿。具体角色、输入隔离和输出边界见 [Contract 与 Writer 协议](contract-writer-protocol.md)。

上述“保留逻辑作用”是要求契约不把不同判断误当重复，不等于每项都要在正文独立展开。只有核心结论和必要推进不得因为文章更短、更顺或已有总括结论而删除或写弱；可选支撑按读者完成当前任务所需的最小量使用。

### 公开表达时的可信度依据与素材缺口

当知识将用于公开内容时，还要区分“观点本身是否成立”和“用户为什么有依据表达”这两个问题。每条公开内容主线至少保留一项可追溯依据：

- 用户亲自经历过的事件或长期实践；
- 用户实际取得并能如实描述的结果；
- 来自其他行业、但能够说清迁移机制的经验。
- 用户已经完成并能回指材料的资料研究、比较、疑问或判断。

不要求用户必须在当前细分领域取得结果；例如用户在其他业务中验证过内容、用户、产品、信任、交付或复购之间的关系，可以据此讨论结构相同的商业问题。但“底层逻辑相通”本身不能替代说明，仍要说清相通的是哪一段机制。

研究材料可以支持研究型分析，但不能冒充亲历。若用户是在教别人行动、赚钱或复制一种方法，亲历、结果或经过实践的可迁移经验应作为主要表达依据；研究可以补充，不能让未验证的方法看起来已经被用户亲自跑通。

如果只有 Agent 的归纳、未经核实的头衔或与命题无关的成绩，应标为待补依据，不得写成用户已经具备的表达资格。

公开表达还应主动寻找能够承担亮点和开头任务的真实材料，但“已询问”和“已经找到”要分开记录。用户确实没有合适材料时，可以完成知识闭环，只在最终整理中标明缺口及其对公开表达的影响；不得为了获得吸引力而补造冲突、数字、经历或反常识判断。

## 3. 来源账本

来源账本整体仅用于内部核对，不进入 `01` 或 `02`；需要单独持久化时须有对应授权。已经在正文用小括号标注的正式理论，其公开注释与可靠来源链接属于 `02` 的知识内容，不等于公开内部账本。知识正文通过准确的主体、自然归因、对象范围和确定程度把必要归属写进判断本身，不把“个人经验”“外部挑战”“待验证判断”等审计标签或证据免责声明说给观众。内部区分：

| 类型 | 含义 | 可否写成用户知识 |
|---|---|---|
| 用户原话 | 用户明确说出的内容 | 可以 |
| 用户确认 | Agent 只改写用户已经完整表达的语义，用户确认表达准确 | 可以，注明经确认；只确认措辞，不补入新知识 |
| Agent 推导 | 根据材料作出的解释或归纳 | 不可冒充用户原话 |
| 外部理论 | 来自学者、研究或通用框架 | 在引用处注明归属 |
| 未验证假设 | 尚缺证据或确认 | 在对应推理处注明待验证 |

若用户否定某个候选，不再把它作为中性选项反复提出。

用户同意一个包含 Agent 新增理论、判断或因果的候选，不会把它转化成用户原始知识；它仍属于 Agent 推导或外部知识。采访阶段用户尚未表达实质判断时，不用候选答案帮助其“识别”，应继续从具体事实外化，或保留为仍然隐性。最终整理可连接材料支持的判断，并用核验理论标注相应机制；这不等于用户原本读过理论，也不要求逐段声明来源类别。依据核对留在内部，正文按主文件自然归因。

## 4. 材料解释与正式理论怎样分工

知识稿先按上一节形成观点主线，再从主 QUD、用户原话、案例、比较、反例和已确认结论中，指出每项正文承诺哪一步尚未解释清楚，建立材料内生解释。它可以定义现象、连接原因与结果、区分相似情况、说明成立条件、给出检验方法或标出适用范围；每一项关系都必须能够回指采访证据。

材料内生解释是对采访知识的显化，不是正式理论。不得为这类解释临时创造“某某理论”或“某某模型”的名称，也不得因为它听起来像理论，就省略对成熟理论的实际核验。

内部先逐项建立：

```text
主线判断 → 采访证据 → 当前解释缺口 → 材料内生解释 → 正文落点
```

无法填写证据或解释缺口时，不得为了完整结构增加解释。解释需要引入新的用户动机、事实、现实因果或结果才能成立时，保留为未验证假设；只解释一个不会改变、支撑或限定主 QUD 的话题时，转为旁支。材料已经把关系说清时，只负责忠实连接，不为显得深刻制造第二条主线。

逐项映射只保证“写什么”。观点契约分析者还须把核心结论与必要推进排成观点主线，决定“先说什么、怎样逐层下探”。解释型主线按材料的真实缺口推进：

```text
真实异常／默认解释失效
→ 第一层答案
→ 该答案仍解释不了的最近问题
→ 下一项判断、证据、必要条件、反例、阶段区分或结果
→ 新出现的必要问题
→ 更深答案或回到个案验证
→ 材料支持的最强结论
```

观点主线为每个主要节点标出一句“本层新判断”，并说明它回答上一节点的什么缺口。这句之前只能保留让读者识别主体、事件和异常所必需的最少情境；删去也不影响判断的理解与可信度时，必须删去。不得先用常规顺序、矛盾标签、推理过程、过渡句或设问把结论拖到后面。“通常 A，这次 B，所以 C”一类铺垫，改为直接说出“B 先于 A”或“决定因素是 C”，再用 A、B 作证据；无法增加判断、必要证据、机制或边界的部分直接删除。解释 Agent 怎样想到结论，不是面向读者的独立作用。

新判断后立即接证据、机制、结果或必要条件。只有当前判断已经给出，又有材料支持的残余矛盾时，才可用问句开启下一层；设问不得代替当前层结论。新层须回答上层残余矛盾，否则作为并列材料或旁支处理；不靠“因此／这说明／另一方面”制造递进。没有真实反预期关系时，按时间、条件、因果或判断依赖组织，不强造反转。

开头优先直接给出异常事实、有材料支持的反预期判断，或全文最强且后文能兑现的结论；不写“反常识的是”一类元标签。强判断后不紧接防御性回拽、重复事实边界或审计式免责。必要条件优先写进准确的主语、对象和情境；结尾完成最强判断或必要回扣即可。材料和契约没有行动建议时，不另加检查清单。

亲历证据保留第一人称，经历中的另一方沿用材料里的实际关系；只有段落已转向一般判断时才改用相应的一般主体。不得为了显得客观，把具体的人和动作统一改成抽象角色。用户已经把材料标为背景、旁支或暂不展开时，优先沿用该定位；只有用户重新定位，或删去其中某部分会使正文承诺失去必要证据或边界时，才按最小量纳入正文。事实和来源边界先在内部处理，不把内部核对说明写成观众正文。

材料内生解释形成后，由 Writer 写出不带理论名称和理论说明的知识稿，并在保存前完成一次同上下文自查：全部正文承诺都有落点且强度一致；读者原有困惑被转化成明确、可使用的新判断；核心段落持续回答前一步留下的必要问题，而不是可任意换序的并列说明；正文平铺直叙、没有整理稿语言，并能直接面向观众朗读。自查不产生`PASS／FAIL`，也不启动新的角色或修复循环；发现问题时由 Writer 在当前写作中直接改正。

Writer 子智能体完成正文与自查并返回主 Agent 后，由主 Agent 冻结正文；每次首次生成知识稿都进入一次理论候选扫描与实际核验，不等待用户知道或提出理论需求。先从正文和观点主线识别值得解释的重要机制，再为每项机制检索成熟理论候选并核对可靠来源。找不到合适候选，或候选无可靠来源、只是换一种说法、不能增加理解时，不强配理论，不生成对应标注。一个理论只需对应其中一处，不必解释整篇；理论步骤不启动第三个写作、审核或编辑子智能体。只有理论注释能完成以下至少一项时，才值得标注：

- 给用户已经说出的现象一个更准确的定义；
- 解释背后的机制，而不只是换一种说法；
- 区分容易混淆的两类情况；
- 提供可以检查或反驳的条件；
- 补充适用边界、失败条件或已知例外。

这里的“判断”必须建立在实际查证上，不是回忆或直觉判断。为每项重要机制完成以下内部记录：

```text
重要机制 → 实际检索结果／候选理论 → 核验的可靠来源 → 采用或排除理由 → 标注落点
```

理论记录没有完成时，不得宣称理论已经核验。候选全部被排除时，每项排除都须有实际核对过的来源与具体理由；用户禁止外部研究或当前无法查证时，保留 Writer 正文并说明对应理论未核验。纳入前说明理论注释增加了哪项准确溯源、标准定义、成立边界或外部挑战；理论数量由准确覆盖决定，不设最低数量。具体冻结、写入和还原动作统一按下一节执行。理论改变用户原判断时，保留用户原判断并把外部挑战另行说明，不包装成用户原先已经知道的认识。

理论不应：

- 在用户知识尚未形成前抢走话语权；
- 作为采访问题中的解释选项，让用户通过同意来认领；
- 为了显得专业而堆名字；
- 把相似概念直接当作事实证明；
- 在采访提问阶段强迫用户补先例、案例或学术来源；正式知识稿的理论核验仍按下一节执行。

## 5. 最终整理前的理论校验与嵌入

主线由用户确认闭环并冻结用户知识快照后，先完成上一节的观点主线、材料内生解释和 Writer 正文，再执行理论候选扫描与实际核验，判断成熟理论能否验证、命名、修正或限定材料已经涉及的重要机制。不得从一个容易搜索的理论出发反向改写、删除或合并观点，也不得改变材料角色或段落顺序。外部理论通过上一节的价值条件时：

1. 优先核对权威原始来源或可靠的一手说明，不用相似概念代替证据；
2. 核对中文正式名称、原文名称、提出者或代表学者、原始出处与年份、理论原意及可靠来源链接。没有单一提出者、统一译名或可靠来源时如实处理，不自行补齐；
3. 正文仍用采访材料和平铺直叙完成推理，只在已经说清的对应判断后加括号，显示可点击的正式名称，例如`（[信号理论](#theory-1)）`。正文不介绍理论定义、学者、研究史或术语，不单设理论段落；理论不得成为句子主语、段落入口、标题或结构依据。同一理论后文不重复标注，不把 Agent 概括或用户经验命名为理论；
4. 每个正文括号都在文末增加对应的`理论注释`，每项使用稳定锚点并简要列出：中文正式名称、原文名称、提出者或代表学者、原始出处与年份、理论原意、在本文中对应的判断、可靠来源链接。理论的标准定义、来源和必要引申只放在这里，不把注释写成长篇课程；
5. 标注后运行`scripts/verify_theory_overlay.py`，确认移除全部理论括号和理论注释后与冻结正文完全一致；失败时撤销理论覆盖并恢复 Writer 正文。理论标注不能把正文改成课堂讲解或第三方分析报告；
6. 若理论只是换一种说法、没有可靠来源、不能增加理解或会把正文带离主 QUD，不写入正文；这个结论必须建立在明确解释缺口和候选比较上，不能凭“感觉不需要”退出；
7. 若理论会修正、收窄或否定用户的重要结论，并列记录用户原判断、外部挑战及证据依据；不得用“是不是这样”要求用户确认，不得改写用户知识快照，也不得把理论静默吸收为用户原有认识。

采用理论时使用以下最小格式，编号按正文首次出现顺序排列：

```markdown
正文中的相关解释。（[正式理论名称](#theory-1)）

## 理论注释

<a id="theory-1"></a>
### 正式理论名称

- 原文名称：
- 提出者或代表学者：
- 原始出处：作品，年份
- 理论原意：
- 本文中的解释：
- 来源链接：
```

嵌入式的判断标准是：正文完全由采访知识和材料内生解释推进，理论只以小括号标注对应关系，名称和注释帮助读者识别、追溯和继续查证，不反过来决定文章结构。若正文出现理论定义、学者、概念史或以理论为主语的推演，说明理论已经接管正文，必须删掉展开并恢复材料句。只有可靠匹配且能增加准确命名、机制解释、成立边界或外部挑战时才标注；没有入选理论不影响完成自查的知识正文交付。

理论校验属于知识采访的收束步骤。只有用户明确要求对一个已经成形的命题做独立、深入的理论研究时，才把它作为后续独立任务，不在当前采访中无限扩展。

## 6. 知识稿组织与表达的执行顺序

先保全并排序观点主线，再按第 4 节由 Writer 写成平铺直叙的知识稿，正文冻结后执行第 5 节的理论候选扫描、实际核验与必要标注。读者任务只校验文章是否让读者获得可理解、可使用的新判断，不决定中心答案、观点顺序或材料去留；这些由主 QUD、采访证据和观点主线决定。表达框架只用于检查读者可理解性、局部与全文连贯及删减保真，不得替代本文件规则，也不得作为正文理论。设计依据与来源见 README。

## 7. 阶段结论状态

每条重要结论应属于以下一种状态：

- 已确认：用户明确表达或确认，证据与边界足以支撑当前用途；
- 暂定：已有方向，但关键事实、机制或边界尚未补齐；
- 待验证：需要外部资料、反例或后续经验验证；
- 已否定：用户已经明确否定，不得重新包装为用户观点。

## 8. 最终检查

按主文件检查两份成果。逐项核对观点契约、观点主线、正文承诺、读者获得、事实边界与材料去留。材料有多层真实反预期关系时，确认各节点按“反预期观点 → 当层解释 → 新矛盾 → 更深解释”推进。确认重要机制已完成理论候选扫描，采用或排除建立在实际核验上；只有存在理论标注时，才额外要求冻结正文还原脚本通过。当前无法进行外部核验时须在交付中明确说明。

来源分层是证据归属，不是文章分割方式。知识稿正文按同一条材料推理推进，只在对应句后标注有增量的理论。没有理论入选时直接交付完成自查的材料内生解释，不把检索过程写入正文；理论未核验时只在交付状态中说明。
